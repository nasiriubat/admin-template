# Module System

## Goal

Projects enable only the features they need.

## Module contract

A module should declare:

- id
- title
- icon
- navigation entries
- routes
- permissions
- feature flags
- settings
- API services
- optional dashboard widgets

## Example

```ts
export const knowledgeModule = {
  id: 'knowledge',
  title: 'Knowledge Base',
  navigation: [
    { label: 'Documents', path: '/knowledge/documents' },
    { label: 'Sources', path: '/knowledge/sources' },
  ],
  permissions: [
    'knowledge.view',
    'knowledge.manage',
  ],
};
```

## Project configuration

Example:

```ts
export const appConfig = {
  name: 'Example App',
  modules: {
    users: true,
    audit: true,
    ai: true,
    knowledge: false,
    billing: false,
  },
};
```

## Implementation

Modules are declared with `defineModule` (`packages/config/src/modules.ts`) in `features/<name>/module.ts` and collected in `features/index.ts`.

- **Navigation** is generated by `buildNavigation`: it drops disabled modules (`AppConfig.modules`) and entries the signed-in user lacks permission for, and groups the result.
- **Mobile bottom bar** uses entries flagged `mobilePrimary` (max four) plus a "More" drawer holding the full navigation.
- **Route guards**: `AdminShell` resolves the current path with `matchRoute` (supports `[id]` segments) and shows the unauthorized or "module is turned off" state.
- **Breadcrumbs** come from module metadata; pages can override them with `<SetBreadcrumbs />`.
- **Permissions** follow `<module>.view` / `<module>.manage`. `*` and `<module>.*` act as wildcards.
- Shipped modules: dashboard, analytics, users, roles, audit, health, logs, jobs, files, feature flags, API keys, webhooks, settings, theme, notifications, account, AI (providers, models, prompts, usage), knowledge base (documents, sources), agent workflows (builder, schedules, runs; see `docs/WORKFLOWS.md`) and billing. `billing` is off by default; enable it in `app-config.ts` for products that charge customers.
- Breadcrumbs only link path segments that are real pages (e.g. `/ai` is plain text above `/ai/models`).
- **Examples module** (`features/examples`, id `examples`, nav group System, badge "Example", no permission) holds the removable demo pages described in `docs/EXAMPLES.md`. It is enabled by `AppConfig.modules.examples`. To remove it, set that flag to `false`, or delete `features/examples`, its entries in `features/index.ts` and `features/_shared/register-mocks.ts`, and `apps/admin/src/app/(admin)/examples`. Ship release builds without it.
