# License Strategy

Do not choose a license accidentally.

## If you release the full product under MIT

Anyone can generally use, modify, redistribute, and sell the code subject to the license terms.

That may be fine for an open source growth strategy, but it weakens exclusivity for a paid template business.

## Possible models

### Open core

Open source:

- core shell
- basic components
- basic themes

Commercial:

- premium themes
- AI module pack
- advanced resource builder
- advanced landing page templates
- commercial support

### Fully commercial

Keep the repository private and distribute under your own commercial license.

### Dual license

Offer one license for open source use and a separate commercial license for specific use cases.

## Recommendation

Before public release, decide what you are optimizing for:

- adoption
- portfolio visibility
- direct revenue
- agency reuse
- community contributions

Do not ship a permissive license until that decision is deliberate.

This file is product planning guidance, not legal advice.
